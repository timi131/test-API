# Проверка услуг REDSMS

Инструмент для проверки услуг [REDSMS](https://docs.redsms.ru/http/) через HTTP API: окно в браузере и командная строка. Нужен только Python 3.9+, устанавливать библиотеки не требуется.

## Что проверяется

| Группа | Услуги |
|---|---|
| Доступ | логин, API-ключ, договор, баланс (всегда первым шагом) |
| Сообщения | SMS, отложенное SMS, Voice, VK |
| Авторизация | Telegram Gateway, Wait Call, Flash Call, PushOK |
| Проверка номера | HLR |
| Каскады | HLR → SMS, PushOK → SMS, Telegram → SMS |
| Массовая отправка | SMS на два номера |
| Только по явному выбору | Ping, Viber |

## Режимы

- **Имитация** (по умолчанию). Запросы уходят с `test=true`, сообщения не отправляются. Проверяются доступ и приём запроса, но не доставка.
- **Настоящая отправка.** Платно: сообщения и звонки приходят на указанный номер. Скрипт ждёт конечный статус каждой услуги, а перед запуском просит ввести `ДА`.

Параметра `test=true` нет в документации, он известен из ответов поддержки REDSMS. Поэтому в режиме имитации скрипт сверяет баланс после каждой услуги и останавливается, если баланс уменьшился.

## Запуск окна

```bash
python3 redsms_gui.py
```

Страница откроется в браузере. Там вводятся логин и API-ключ, выбираются режим и услуги. Чтобы закрыть, нажмите `Ctrl+C` в терминале.

Для первого запуска удобно выбрать режим «Имитация» и только HLR.

## Шаблоны

Вкладка «Шаблоны» хранит локальную копию шаблонов операторов для SMS и VK. Регистрируются шаблоны только в личном кабинете REDSMS: API для этого нет, поэтому окно ничего не меняет на стороне REDSMS.

Если отправляемый текст не совпадает с зарегистрированным шаблоном, сообщение тарифицируется как рекламное. Окно помогает проверить это заранее:

1. Сохраните шаблон с переменными `%w`, `%d`, `%d+`, `%w{1,n}`, `%d{1,n}`, типом и примером. Окно проверит правила из [документации](https://docs.redsms.ru/knowledge-base/templates/sms/) и совпадение примера.
2. На вкладке «Проверка» выберите шаблон и заполните значения. Окно покажет итоговый текст и найдёт расхождения с шаблоном.
3. Запустите имитацию SMS. Если REDSMS вернёт другой тип тарификации (`traffic_type`), чем у шаблона, проверка завершится ошибкой.

Локальная проверка приблизительная, окончательно решает оператор. В шаблонах VK переменные записываются в произвольном виде, поэтому их текст не проверяется: окно подставляет его как есть.

Шаблоны лежат в `redsms_templates.json` рядом со скриптом и не попадают в git. В командной строке тип проверяется так: `--sms-text "текст" --expect-traffic auth`.

## Логи

Вкладка «Логи» показывает текущий запуск и прошлые файлы `redsms_test_*.log`: запросы и ответы API, смену статусов, время и `uuid`. Есть поиск, фильтр ошибок, показ опроса статусов, копирование и скачивание. При просмотре очень большого файла показывается его конец.

## Запуск на сервере (REDSMS «Проекты»)

В репозитории есть `Dockerfile`, поэтому «Команду запуска» заполнять не нужно. Настройки проекта:

- **Как открывать:** по адресу `/apps/<имя>/`. Подойдёт и отдельный порт.
- **Порт приложения:** любой свободный, например `8501`. Приложение берёт его из переменной `PORT`.

Что меняется на сервере (`python3 redsms_gui.py --server`):

- Запросы без заголовка `X-User` отклоняются. Его подставляет прокси платформы после входа, поэтому порт контейнера нельзя открывать напрямую.
- Запуски, логи и шаблоны у каждого пользователя свои.
- Ключ передаётся на сервер проекта, хранится в памяти только на время проверки и не пишется на диск.
- Запросы к REDSMS идут с IP-адреса сервера. Если в личном кабинете включён белый список IP, этот адрес нужно в него добавить.
- Шаблоны и логи лежат в `/data` внутри контейнера и пропадают при пересборке проекта, потому что платформа не подключает постоянный том. Хранятся последние 30 логов.

## Запуск из командной строки

Логин и ключ задаются только переменными окружения:

```bash
export REDSMS_LOGIN=ваш_логин REDSMS_API_KEY=ваш_ключ
```

```bash
python3 redsms_test.py --list
```

```bash
python3 redsms_test.py --to +7XXXXXXXXXX
```

```bash
python3 redsms_test.py --to +7XXXXXXXXXX --live --services hlr,wcall
```

Voice, VK и массовой отправке нужны дополнительные параметры: `--voice-from`, `--vk-from`, `--vk-text`, `--to2`. Без них эти услуги пропускаются с указанием причины. Остальные параметры показывает `--help`.

Код выхода: `0` — ошибок нет, `1` — есть ошибки, `2` — запуск отменён или неверные параметры.

## Безопасность

- API-ключ не записывается на диск и не попадает в лог. В запросах передаётся только подпись `md5(ts + ключ)`.
- В логах номера получателей замаскированы.
- На своём компьютере окно работает только на `127.0.0.1`. Запросы к нему требуют токен, который создаётся при запуске, а чужие адреса в заголовке `Host` отклоняются. Поэтому посторонний сайт не сможет запустить отправку.

Логи `redsms_test_*.log` создаются рядом со скриптом и не попадают в git.

## Что учесть

- Отложенное SMS проверяется только в имитации: настоящее сообщение нельзя отменить.
- Кнопка «Остановить» прекращает новые запросы, но не отменяет уже созданные сообщения.
- Вебхуки не проверяются: для этого нужен публичный адрес.
- Flash Call и Voice: по документации операторы могут возвращать неверные статусы, поэтому `OK` не гарантирует, что звонок был на самом деле.
- Wait Call работает без параметра `text`: режим с диктовкой кода снят с поддержки. `replacedFrom` приходит без `+`, поэтому скрипт показывает номер для набора с ним.

## Файлы

- `redsms_test.py` — логика проверок, командная строка и её тесты.
- `redsms_gui.py` — окно в браузере.
- `redsms_templates.py` — разбор и проверка шаблонов, их хранение.
- `test_redsms_gui.py`, `test_redsms_templates.py`, `test_redsms_server.py` — тесты окна, шаблонов, логов и серверного режима.
- `Dockerfile` — запуск на сервере.
